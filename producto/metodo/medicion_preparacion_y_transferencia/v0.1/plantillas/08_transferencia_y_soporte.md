# Plantilla de transferencia, recepción y soporte

Versión 0.1 · K17 · Campos empresariales vacíos

Usar con [transferencia y cierre](../06_transferencia_y_cierre.md). También permite cerrar Diagnostic conforme a K01 sin construir el sistema posterior. Agrupar índice, recepción y pendientes cuando facilite la continuidad; no crea un cuarto maestro de Go2Rev.

## Estado, contenido y recepción

| Campo | Regla | Valor |
|---|---|---|
| Referencia | K17/revisión, autor, fecha, ubicación y estado documental | |
| Encargo y salida | K01/revisión, K06/DEC, ámbito contratado y decisión de cierre | |
| Obligación recibible | Entrega, destinatario, criterio y compromiso al que responde | |
| Estado y fundamento | Evaluación, diseño, preparación comprobada o entrega parcial; evidencia por ámbito | |
| Actuaciones observadas | Referencias originales cuando existan; separar de cumplimiento integral y resultado futuro | |
| Índice por tarea | Qué usar y dónde, fuente editable, revisión, derivados y precedencia | |
| Dependencias | Archivos, fuentes externas y medios necesarios; enlace distinto de copia disponible | |
| Acceso y derechos | Receptor/propietario, permisos y mecanismo conforme a K01; sin secretos ni redistribución presumida | |
| Integridad y recuperación | Evidencia de selección/apertura/lectura o transporte pertinente; límite de lo comprobado | |
| Guía de continuidad | Cómo entrar, recuperar, actuar, registrar/transmitir y revisar; tarea, responsable y ayuda | |
| Medición y revisión | K13, dónde consultar, decisión, responsable y evento/periodo pertinente | |
| Recepción efectiva | Quién recibe, qué confirma, cuándo y con qué reservas; no presumir por envío | |
| Efecto económico | Condiciones acordadas sobre evaluación, trabajo realizado/no realizado y cierre | |

## Pendiente y acompañamiento — bloques agrupables

| Campo | Regla | Valor |
|---|---|---|
| Pendiente y causa | HUE/CON/defecto/decisión/dependencia localizable; conservar su naturaleza | |
| Efecto y límite | Obligación/uso que impide o condiciona, sin presentar cumplimiento integral | |
| Responsable y condición | Quién resolverá, evidencia/corrección necesaria, momento pertinente y receptor | |
| Naturaleza del trabajo posterior | Corrección debida, consulta cubierta, dependencia o ampliación según K01 | |
| Soporte incluido | Acciones, medios, responsable y límites de acompañamiento ya acordados | |
| Atención y resolución | Condiciones/calendario de respuesta separados de resolución y dependencias externas | |
| Fin de acompañamiento | Evento/fecha/condición pactada y obligaciones remanentes; sin operación permanente implícita | |
| Incidencia y cambio | Cómo informar, limitar uso, asignar productor, corregir y comprobar lo afectado | |
| Aprendizaje autorizado | Regla general candidata, causa, alcance y autorización; fuera de fuentes generales quedan datos de prestación | |
| Cierre y continuidad | DEC/recepción, siguiente decisión y localización del estado vigente | |

La autoridad de recepción no aumenta la evidencia. Conservar originales y versiones que sustentan el cierre, sin trasladar su historial completo a la entrada operativa.

## Aplicabilidad de los bloques

Antes de emitir K17, completar el núcleo de [N17 Transferir y cerrar el alcance](../../../operacion_conversacional/v0.2/10_primera_pasada.md). Las reglas CONTR, EVAL, USO y de variante de esta plantilla mantienen su momento de exigibilidad. Un bloque condicional se completa cuando afecte al resultado; documentar la condición que lo hace aplicable o su exclusión. Una ausencia material queda localizada y limita el uso dependiente. La cabecera común se registra una vez por artefacto.
